# Wave 13 plan (integrated, from phase A)

Written 2026-10-30 by the wave 13 phase A architect, after 11 topic designs with physics and engineering reviews and a critic pass. Specs: ~/.cache/mark1-build/w13/specs/ (the _v2 files). Phase A report: docs/wave13-phaseA-report.md.

WAVE 13 INTEGRATED PLAN, REVISION 2 (architect, 2026-10-29). This version applies the critic's 25 points. Points not taken are listed at the end.

0. WHAT THIS IS
Wave 13 gives the sim real stuff, real heat, real bodies and real parts. Eleven topics were designed and reviewed: T1 composition, T2 records, T3 layers, T4 mixtures, T5 scheduler, T6 matter, T7 body heat, T8 cold, T9 material, T10 injury, T11 mechanisms. This plan joins them with three things: one shared state model (one name per thing), one owner per number and per file, and a build order that keeps golden bit-identical until a capability is switched on on purpose.
Phase A (now, in parallel with wave 12) builds NEW pure modules and their tests in the sandbox. It edits no existing file. Phase B (after wave 12 lands as base19) wires them in. Phase B is split in three: 13a = plumbing, golden SAME for every case; 13b = the four switches that everything else rests on (cold, mixtures, body heat, material laws); 13c = the rest (matter processes, layers, smoke, records, injury, mechanisms, contact, tier 1 skip, crafts). Each switch is its own declared diff.
New in revision 2: four small lanes in batch 0 (A-O frozen oracle, A-S sourced numbers, A-M early heavy measurements, A-G10 body numbers). Phase B gets B4b (particle and bond seam), B8 (body sheet in scenes), C4b (smoke opacity), C8a/C8b (split to fix file order), C12 (craft proofs), C13 (contact events and slip law).

1. SHARED STATE MODEL (one name for each thing)
Cell (lattice arrays):
- mat, fl: VIEWS of the mix (stored uint8, kept true by one rule). Once a cell is mixed nobody writes them directly; writers use set_mat / set_solid / set_fluid.
- smass, fvol, fpot, E, skin, rubble, eid, edge, fallh: unchanged.
- scomp, fcomp: mix ids of the cell solid and fluid; 0 = pure (old path). Lazy; w.mixes_live guards every gather.
- dmg: damage 0..0.999 (T9), one writer add_damage(). Slow overload is a separate sparse float64 creep dict, not dmg.
- bzone: overlay id of a voxel (T7; person slot x 16 + zone). The same mechanism can carry any face overlay (a coat on a statue), so it is not a body flag.
- ice_g: lazy ice grams in a non-ICE cell (T6).
- cls: 1-byte outdoor class cache (T8), outside the world like _GEO.
- Gas store (T6): lazy named arrays of grams EXCESS over a fixed reference (vapour, mist, CO2).
CARRIED rule (changed after the critic): CARRIED and AS_BODY stay exactly as in base19 (eid last). Every new carried field goes in ONE optional list CARRIED_OPT (field, body key), handled in _lift/_put ONLY when the array exists (getattr(self, f, None) is not None) and defaulting to 0 for a body lifted without the key. Members: scomp/fcomp (T1), dmg (T9), bzone (T7), ice_g (T6). So B2 cannot crash a lift, test_things.py:955 is untouched, and old body hashes cannot move. A test proves old AS_BODY hashes are unchanged.
Species and mixes (T1): one species registry (ids 0-16 legacy, 17-63 seed, 64-95 gases, 96+ packs); FORM = DISSOLVED, CRYSTAL, GRAIN, BOUND (liquid = DISSOLVED, gas = the L2b vector); component key = species<<10 | form<<8 | size; MixTable = shared immutable rows of integer weights out of 2^24 (w.mixes). Id ranges: mat 0-11 legacy, 12 ICE, 13-31 new skeleton mats, padded to 64; fluid ids 0-8 legacy, 9+ new, padded to 64; table rows: solids 0-63, fluids 64-127, user mixes 128 up. Retired materials are never renumbered: a retired name keeps its id and names a successor (OpenWorld item 7).
Face (surface): LAYER stack (T3), int64 key (tag 0 cell face, 1 record, 2 body region, 3 outdoor column). ONE face-environment bundle is passed to the heat face law: overlay tables (T7 BH1 core-to-skin, BH2 convection/emissivity/area, BH3 series resistance, keyed by overlay id), T3 emissivity overlay and layer resistance, T8 environment temperature and room id, T4 per-cell boiling point, T10 face-flux readout (FF). Convection law and emissivity are DATA COLUMNS of the face material row (default = old constants; the FLESH row gets the ISO law and 0.98), not a body test.
Record (T2): one pool family: SECTION, SHEET, STRAND, CONDUIT, LOT, VESSEL, JOIN, GROUP, and MECHANISM (content T11, pool T2). Shape-only records ride on a host that owns the grams; record-owned matter (glue line, lots, cup contents) is counted by ONE ledger term, records_owned. Other stores (layers pool, p['body'] bones and wounds, p['heat']['clothes'], mechanism dicts) are deliberately separate stores for speed and shape, but each exposes a read-only header view (host, rid, class, totals, audit hook) through record_view.py, so records_audit and the user's one-schema rule see them all. Bones and wounds stay person records in wave 13.
Person: p['sheet'] (T7 owns, built from bodysheet), p['heat'] (T7), p['body'] (T10), p['fatigue'] (stays T5 sleep view; limb fatigue via fatigue_of), p['incap'] (legacy shim, see switch ledger), p['skill'] (per act, default from bodysheet, hash-drawn).
World: w.climate, w.t_out, w.t_sky, w.air_rh (T8 publishes, T6 reads), w.slow (None default), w.records, w.layers, w.mixes, w.mech_in, w.made{water,latent}.
THE BOOKS (one list in ledgers.py; each term has name, sign and ONE writer; a manifest test asserts this and that total_energy plus books closes on every proof scene): gone[species], shed, recast, quant, f32, squeeze (T1); records_owned (T2); outside_booked{rad, edge, air_film, air_far, shift, top, ground, ref_shift, mrt_resid} (T8); boiled_J, melted_J, frozen_J, dissolved_J (T4); made[water], made[latent] (T6); mech_in (T11); pool, stores, work_out, warm-up injection (T7); pooled_ml, edema_ml (T10); layer mass and enthalpy (T3); slow residual (T5).
ONE-FLOW RULE (critic 3): a joule that an actor delivers to a mechanism is debited from that actor's stores and credited to work_out (T7). mech_in is used ONLY for releases with no actor (a spring let go, a door slam from stored swing, a burnt jamb). deposit() takes an actor argument and picks the book; the manifest test fails if one act books both.

3. INTERFACES BETWEEN TOPICS
3.1 Composition, material record, mixtures, matter.
- T1 owns identity (species, forms, keys, rows), exact take/put/convert, and pure-substance data (Masson phiV0 and Sv, c_app, k_app, mu_rel, Antoine, Tm, Lf). Nobody keeps a second copy; T4 and T6 stand-ins carry a cross test.
- T9 owns every MECHANICAL number. matrec.blend() computes E, strengths, hardness only and calls mixrules for density, c, k, viscosity (cross test fails on any second k implementation). A new skeleton species gets its own mat id and a MatRec row; T1's like row is only the fallback. mixrules.register_rule is the one API. MatRec has weibull_m and eps_f (= ductility) and a props(key, grain) adapter.
- Dependency chain for legacy tables (critic 7): frozen oracle (A-O, from base18) is the ONE reference. T1 legacy_tables and T9 legacy_views are both tested against it. At wiring: oracle -> matrec -> legacy_tables -> materials. species 0-16 read materials; materials reads matrec; the oracle test is the guard against circularity.
- T4 owns every mixture QUANTITY and the one coupled solver phase_step. It reads MixTable only via to_dense and calls T1 convert(). Null id is 0. T1's mass-exact fluid blend replaces T4's volume blend.
- T6 owns PROCESSES. It uses T1 take/put for grams and T4 for psat, aw, boil, freeze, phase_step. fvol of a solution cell is the SOLUTION volume. solution.py takes the volume rule as an injected function.
- Ice: T6 owns law and numbers (ICE_ROW dict exported from icephase.py, ingested by matrec in B3); mat 12 is T1's view of water BOUND; T4 gives liquidus and Lfus(T).
- One water set: Lf = 333.55 J/g at 0 C, Lfus(T) = 333.55 + 2.09 T, psat from T4 mixwater (IF97), Masson 16.62/1.87 from the T1 species record.
3.2 Records, layers, mechanisms, bones.
- T2 owns the pool, hand-over rule (0.5 cell down, 1.0 up) and joint capacity library. T11 owns MECHANISM fields and fastener formulas (fasteners.py); T2 joinery imports it (nails stay in joinery).
- Layers key tag 1 -> record id, tag 2 -> body region. tissue.ZONE_OF_BONE is the zone source; anatomy.REGION_OF_ZONE maps 14 zones to 11 regions. Clothing (series resistance at the skin face) and dirt layers (outside the garment) add in series.
- ONE blow seam in bodies._spend: handler order mechanism -> record cut -> shatter threshold x (1-D) -> cell law. T10 landing energy goes through the same seam.
- Damage: matdamage.combine is the only combine (copied in phase A, imported at wiring; X checks).
3.3 Scheduler, body heat, cold.
- T5 Twin protocol joins T7 bodynodes via an adapter. The T5 breath twin uses the tick law's own recurrence (golden SAME).
- T8 gives T5 ClimateDrive and _unsettled() reasons (off_rest, interface, sky_drive). Tier 1 is opt-in per call, never in golden or harvest.
- T7 reads T8 via w.env_t4(cell) and w.t_sky. AirSink implementations: open-world default (gone, shed), GasStore adapter for vapour (C3, airsink_gas.py), sealed-room region sink (C10, airsink_world.py), GAS vector for O2/CO2. Tick path and skip path call the same sink.
- Heat laws: ONE face-environment bundle and ONE new signature for _face_heat and its numpy twin, in B1. All defaults reproduce the old constants.
- Phase engines: T4 phase_step is the one coupled solver; T3 and T6 keep private stand-in bisections with cross tests. Stefan ice: T6 law, T5 front is the integrator of the same equation, T8 drops its copy. Diffusion: T6 transport (lattice), T2 thinheat (records), T5 fick (skips), T1 partition (selector).
3.4 Wave 12 reflex contract (reflex.py). Thermoregulation rows are kind 'continuous' (tau_s lag, dead time, works_when), work asleep and unconscious, Schmitt events (on 10%, off 5%): verbs shivers, sweats. T10 adds withdraw (trigger at heat pain 0.5) and fall_grab with yields_to via the _chose tag. Slowing reads fatigue_of(p, limb). The balance reflex owns recoil.
